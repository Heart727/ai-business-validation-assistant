# 新手使用指南：AI 经营分析与 7 天验证助手

公开入口：[经营验证工作台](https://business-validation-lab.vercel.app)。访客无需登录，也不用安装软件或配置 API。准备一个普通浏览器和几分钟时间即可体验。

可以先看 [90 秒操作视频](https://business-validation-lab.vercel.app/static/demo/index.html)，再按下面步骤亲自操作。视频配有中文字幕和合成讲解，已有报告与本次操作分别标明。

这是求职展示用的 **DEMO 项目**，只允许虚构经营资料和虚构执行记录。它把一个经营问题整理成摘要、证据、推断、缺失信息、风险及七天行动计划，并将资料和结果保存到专用飞书演示表。AI 提供的是待验证假设，不是收益承诺，也不代表已经开展过真实经营实验。

## 一、先了解你会得到什么

一次完整体验分成两部分：

1. **生成计划**：选择十份虚构模板之一，修改表单，确认资料全部虚构，再提交 AI 分析。成功后显示报告，并保存到飞书。
2. **记录执行**：在第 1 至第 7 天的行动下填写状态、实际指标和结论，逐天保存。这里的“实际指标”是执行记录字段；公开演示仍只能填写虚构观察值。

保存执行记录或刷新查看报告不会再次调用 AI，也不会自动重新评估经营结论。它们会访问已保存的记录。访客只能通过本次记录的访问令牌查看和修改这一条记录，不能浏览整张飞书表。

## 二、第一次操作：选择模板并修改资料

### 第 1 步：打开公开网页

打开 [公开演示](https://business-validation-lab.vercel.app)，等待模板加载。如果页面明确标注“静态预览”或“实时服务未启用”，当前展示的是固定示例，不能当作刚刚完成的 AI 分析或已保存的记录。要体验完整保存流程，需要实时服务可用。

### 第 2 步：选择一个虚构模板

页面提供十种起点：早餐配送工作室、街区咖啡店、线上花店、私人训练工作室、宠物美容店、二手服饰店、学习辅导工作室、婚礼策划工作室、商用清洁服务和家庭烘焙工作室。

第一次建议选“虚构样例：早餐配送工作室”。模板会填入经营资料表单，你可以在规定的字段里修改内容。模板用于降低填写门槛，不是十家真实客户的资料，也不是十次真实调用的验收证明。

### 第 3 步：把经营问题写具体

先沿用大部分模板，只改现有指标和目标，比较容易看懂分析依据。下面是一套**完全虚构的教程输入**，不是真实商家的经营数据：

| 表单字段 | 可以这样填写 | 最多字符数 |
| --- | --- | --- |
| 场景名称 | 虚构样例：早餐配送工作室 | 80 |
| 行业 | 早餐餐饮 | 60 |
| 产品或服务 | 办公区早餐套餐预订与配送 | 300 |
| 目标客群 | 需要工作日早餐的周边小型办公室 | 300 |
| 经营问题 | 每天临时订单波动大，希望验证提前预订是否有助于安排备餐量 | 600 |
| 现有指标 | 虚构基线：每天 40 单，其中提前预订 8 单，预订占比 20%；每天约剩余 6 份 | 600 |
| 预算范围 | 虚构预算：一周最多 300 元 | 100 |
| 目标 | 在 7 天内观察提前预订占比能否达到 30%，同时记录剩余餐品数量，不直接扩大投放 | 400 |
| 成功判定标准 | 虚构门槛：七天合计预订占比至少 30%，日均剩余餐品不超过 3 份，预算不超 300 元；数据不足时记待验证 | 300 |
| 时间限制 | 7 天验证 | 100 |

每项都要有内容，不能只填空格。场景名称保留以“虚构”开头的标记。超过长度时，缩短描述并保留关键数字和问题；页面接受的是这些经营字段，不是无限长度的自由聊天。

填写时把三件事分清楚：现有指标描述起点，目标描述希望观察到的变化，经营问题描述你还不确定的事情。例如“现有预订占比 20%”是这份虚构资料里的基线，“希望达到 30%”是目标，不能把目标写成已经达成的结果。

### 第 4 步：确认全部资料为虚构

检查所有字段，然后勾选“仅使用虚构资料”的确认项。不要输入真实客户姓名、联系方式、订单明细、员工资料、公司内部数据或任何密钥。执行日志也遵守这一规则。

系统会做字段长度和部分敏感内容检查，但检测不能保证发现所有个人信息或凭证。勾选确认只是你的使用声明，不会把真实资料自动变成安全的虚构资料。

### 第 5 步：提交分析，等待完成

点击分析按钮后，保持页面打开，不要连续点击。页面会为这次提交生成一个请求 ID，格式为 UUID，可把它理解为“本次提交的编号”。系统先建立或查找对应的飞书演示记录，再调用 AI；分析通过结构校验并保存后，页面才显示完成结果。

公开演示的**分析、重试、恢复、保存四类请求合计每个 IP 每 10 分钟最多 5 次**。刷新恢复占用一次，保存一天占用一次；连续填写并保存七天，需要分几个窗口进行。同一办公室或家庭网络可能共享一个出口 IP。看到 `429` 时保留未保存内容与恢复凭证，等待当前窗口恢复，不要反复点击。

AI 服务和飞书服务都需要时间。看到错误提示时，按本文第五部分恢复；不要把“正在处理”或“分析生成但保存失败”当成已完成。

## 三、看懂报告：先看依据，再看动作

成功后检查下列内容：

| 报告部分 | 新手应该看什么 |
| --- | --- |
| 经营摘要 | 本次建议优先验证哪个问题，有没有超出你填的预算和时间 |
| 证据 | 哪些内容来自输入资料；这里的证据仍是你提供的虚构基线，不是外部核实过的事实 |
| 推断 | AI 对问题原因的可能解释；不要把“可能”直接当成确定结论 |
| 缺失信息 | 还需要收集哪些观察值，才能判断假设是否成立 |
| 风险 | 样本、成本、执行条件或其他因素会怎样影响判断 |
| 第 1 至第 7 天行动 | 每天做什么、看什么指标、按什么条件继续或停止 |

例如，AI 可能建议先统一预订统计口径，再小范围验证提醒方式。但具体措辞和动作会随输入与模型输出变化，本教程不保证每次生成同一份计划。七天动作必须覆盖第 1 至第 7 天，各一天一项。

显示成功意味着本次资料快照和分析结果已写入专用飞书 DEMO 表。访客查看的是网页上的这一份报告；无需登录飞书，也不需要拥有表格访问权限。

## 四、填写七天执行记录并保存

### 第 6 步：找到对应日期的记录区

在已成功保存的报告里找到第 1 天动作及执行记录。先读该天的指标与判断条件，再填写：

| 项目 | 用法 |
| --- | --- |
| 状态：待执行（`pending`） | 还未完成，或需要继续补充观察 |
| 状态：已完成（`completed`） | 当天动作已完成，必须同时填写实际指标和结论 |
| 状态：已跳过（`skipped`） | 未执行该动作；建议在结论里说明原因，不要编造完成数据 |
| 实际指标 | 记录观察值和统计口径，最多 400 字符 |
| 结论 | 对照当天条件说明下一步，最多 400 字符 |

### 第 7 步：练习保存一条虚构记录

以第 1 天为例，先确认当日动作适合下面的记录。若 AI 生成的是其他动作，请相应修改虚构记录内容：

- 状态：已完成。
- 实际指标：`虚构演示记录：当天 42 单，其中提前预订 8 单，预订占比约 19%；剩余餐品 5 份。`
- 结论：`虚构演示结论：先确认各天采用相同统计口径。一天的数据不足以判断提醒方式是否有效，继续按计划观察。`

点击该天的保存操作，等页面确认保存成功后再离开。未保存的输入不能当作已写入飞书的记录。标记“已完成”时，如果指标或结论为空，需要补齐后再保存。

每一天单独保存，更新第 2 天不会覆盖第 1 天。以后可以修改同一天的状态、指标和结论，再次保存会更新该天当前记录；不要把这理解为完整的历史版本或审计日志。

**保存执行记录只写入飞书，不重新调用 AI，也不改写原分析。** 七天全部标记完成只表示你保存了七条完成记录，不证明经营目标达成，更不证明真实收入或利润增加。

### 第 8 步：刷新，查看最近一次成功报告

分析成功后，浏览器会保存该记录的请求 ID 和专属访问令牌。使用**同一设备、同一浏览器、同一浏览器用户配置**重新打开相同站点或刷新页面，可恢复最近一次成功保存的报告，并读取已保存的七天记录。

注意以下边界：

- 恢复入口只保留最近一次成功记录，不是历史报告列表。再次成功分析后，最近记录会切换到新报告。
- 换手机、换浏览器或清除站点数据，不会自动找回记录。可以事先点击「复制报告恢复码」，然后在新浏览器的「恢复已有报告」中粘贴并读取；没有恢复码时无法按账号找回。隐私模式关闭后也可能丢失本地凭证。
- 刷新恢复的是服务端已保存的内容，不是尚未保存的编辑，也不能保证恢复失败或仍在处理中的请求。
- 网页产生的编辑记录仅有请求 ID 不能授权查看或修改日志，还需要匹配的访问令牌。项目没有账号登录或账号找回；恢复码是手动转移该条记录访问权的方法。
- 清除浏览器数据不会删除飞书里已经保存的 DEMO 记录。服务端用于签名的密钥轮换后，旧访问令牌会失效。

不要公开访问令牌、浏览器存储内容或包含它的调试截图。令牌虽然不是 Dify、DeepSeek 或飞书的服务商凭证，但持有它的人可以访问并修改对应记录。共用浏览器的人也可能恢复最近报告，因此不要在公共设备上留下访问资料。

展开「查看这份报告的资料快照」，可以检查系统保存的是哪一份经营问题、指标、预算和目标。完成恢复或日志保存后，这里显示从演示表读回的资料；它不会跟着上方新选择的模板改变。

需要换设备时，先点击「复制报告恢复码」并妥善保存。在新设备打开同一个网站，展开「恢复已有报告」，粘贴原样的恢复码，点击读取。读取成功后会恢复报告、资料快照与已保存日志，也占用一次共享调用额度。

## 五、失败时怎么处理

### 分析失败：用同一输入和同一 UUID 重试

如果页面提示超时、AI 输出不合格或飞书暂时不可用，保留原页面，并使用失败提示对应的重试操作。重试应沿用**原模板、原表单内容和原请求 UUID**，不要一边改资料一边重试，也不要用连续的新提交代替重试。

系统会先按原 UUID 查找记录，再复用同一条记录；若已经完成，会返回已保存的结果。这是减少重复写表的机制，不保证一次重试就能修复外部服务故障，也不保证所有失败情况下都不会再次消耗 AI 额度。

如果你确实要更改资料，请启动一次新的分析，让页面生成新的 UUID。旧 UUID 对应的资料快照不能被新内容覆盖；看到 `request_content_conflict` 就表示同一编号收到不同内容，应该改为新分析。

| 遇到的情况 | 下一步 |
| --- | --- |
| 表单为空、超长或未确认虚构资料 | 补齐或缩短字段，确认只含虚构资料后再提交 |
| 内容被敏感检查拒绝 | 删除联系方式、个人信息、密钥或不符合演示用途的内容，不要尝试绕过检测 |
| 分析超时、输出异常或飞书读写失败 | 保持原输入和原 UUID，稍后使用重试；持续失败时由项目所有者检查外部服务 |
| `request_content_conflict` | 不覆盖旧记录；需要修改资料时启动新分析，使用新 UUID |
| `429`／请求过于频繁 | 等待限流窗口过去后再操作，重试也可能触发限流 |
| 保存当天记录失败 | 保留当天填写内容，稍后重试该天的保存；不要为了保存日志重新跑 AI 分析 |
| 刷新后找不到报告 | 检查是否使用原浏览器及用户配置、本地站点数据是否仍在、实时服务是否可用 |
| 访问令牌无效、记录不存在或尚未完成 | 当前无法读取或保存；不要猜令牌。由所有者核对记录和配置，必要时重新完成一次虚构分析 |
| 页面显示静态预览 | 仅用于理解固定示例；没有本次实时生成或保存的成功证据 |

错误提示可能只显示安全描述或稳定错误码，不会展示外部平台响应全文。向项目所有者反馈时，可以提供发生时间、操作步骤、错误码和请求 ID；不要附访问令牌、凭证或真实经营资料。

## 六、项目所有者如何核对飞书保存结果

只有拥有权限的项目所有者或协作者，才可以打开 [专用飞书演示表（非公开）](https://qcngavuynwd3.feishu.cn/base/VYR4bKwbra78eXs9sMvcmyLMnsd?table=tblMOuyhUydfHArG&view=vewdYYnCuU)。这个地址不是访客入口，也不是面试官必须能打开的公开链接。

1. 使用有权限的飞书账号打开表格，按网页对应的请求 ID 找到记录。
2. 检查演示标记为 `DEMO`，资料快照对应提交时的修改内容，而不是原始模板或后来修改的表单。
3. 检查分析处理状态及摘要、观察、风险和七天行动。处理中或失败记录不能当成成功记录。
4. 保存一天的执行日志后，检查对应的“第 1 天”至“第 7 天”独立执行记录字段及更新时间。其他天的内容应保留。

记录字段中的 `completed` 分析状态表示报告完成；某一天执行日志的 `completed` 表示该天已填写完成。两者都不是“真实经营验证成功”的证明。向外展示时用脱敏截图或公开页面，不要为了演示把整张表改为公开。

## 七、体验完之后能说明什么

你可以说明自己体验了“虚构资料 → AI 计划 → 飞书保存 → 每天补充虚构观察值 → 刷新读取”的流程。你不能据此声称已经服务真实商家、做过七天实地实验、提高营业收入，或验证了 AI 建议的经营效果。

项目背景与已有证据见 [项目案例](case-study.md)，求职表述和演示话术见 [简历与面试材料](resume-project.md)。当前教程介绍交付版的操作流程；真实验收范围应以项目后续补充的、可核对的证据为准。
