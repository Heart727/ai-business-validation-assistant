# 90 秒项目演示

[打开视频观看页](https://business-validation-lab.vercel.app/static/demo/index.html) · [下载 MP4](https://business-validation-lab.vercel.app/static/demo/project-demo.mp4) · [亲自体验](https://business-validation-lab.vercel.app/)

视频录制的是 2026-10-13 的九字段版本；2026-10-14 新增必填「成功判定标准」，当前表单以公开网页为准，验证见 [改需求练习](change-request-exercise.md)。视频分辨率为 1440 × 960，90 秒，约 5.2 MiB。画面附中文字幕，旁白为中文合成语音；播放页可选择讲解字幕，也可下载视频后播放。

## 视频里展示了什么

| 时间 | 操作 | 可核对的内容 |
| --- | --- | --- |
| 0–12 秒 | 打开公开网页 | 无需登录的虚构演示入口 |
| 12–30 秒 | 选择咖啡店模板并修改资料 | 每天 60 杯、复购 20%、一周预算 200 元、七天验证目标 |
| 30–49 秒 | 读取此前已生成报告 | 真实历史报告来自飞书；摘要区分证据、推断和缺失信息 |
| 49–61 秒 | 查看七天行动 | 每天行动、观察指标与判断规则 |
| 61–78 秒 | 填写并保存第 1 天日志，刷新页面 | 真实写入飞书，刷新后指标与结论读回一致 |
| 78–90 秒 | 展开已保存资料快照，展示项目入口 | 原始输入可核对，代码与验收证据可访问 |

本次没有点击提交新分析。视频清楚标明“此前已生成报告”，不把恢复结果当成本次新生成；保存和刷新没有再次调用 AI。录制中的 `/api/record`、`/api/actions`、`/api/record` 三次请求均为 200，脱敏核验见 [录制证据](video-recording-evidence.json)。报告最初的真实生成过程见 [线上验收记录](production-browser-verification.json)。

字幕和阶段提示是录制专用叠加层；录制使用公开网站及真实服务，没有用模拟接口替换保存或恢复。录制没有展示恢复码、访问令牌或平台凭证。所有经营数据及执行日志均为虚构，不能据此宣称真实商业成果。

## 面试时怎么展示

先播放视频，随后打开公开项目，让面试官选择模板自行尝试。可以用一句话介绍：

> 这个个人项目用 Codex / AI 辅助开发，把受限的虚构经营资料接入 Dify / DeepSeek，并在飞书保存报告和七天执行记录。我会结合代码和验收证据，说明自己实际参与的需求、配置与核对。

现场生成需要外部服务可用，耗时可能变化。分析、重试、恢复、保存共享每 IP 每 10 分钟 5 次的额度；视频可以先帮助对方了解结果，再进行一次完整体验。

## 重新录制或更换旁白

使用 [简历和面试材料](resume-project.md#四90-秒面试演示脚本) 中的流程。录制前准备一份仅包含虚构资料的已保存报告，使用浏览器全屏录制或 OBS。展示旧报告时明确标注“已有结果”；展示新生成时保留等待和错误提示，不用旧结果冒充新结果。

视频的 [SRT 字幕](../static/demo/project-demo.srt) 和 [WebVTT 字幕](../static/demo/project-demo.vtt) 可复用。可以按以下讲解文本录制自己的声音；个人职责应调整为自己实际参与且能解释的范围。

1. 这是我的个人求职作品：AI 经营分析与七天验证助手。网页公开可用，无需登录。全程只演示虚构资料。
2. 选择咖啡店模板，填写基线、预算和目标。这里是每天六十杯，预算两百元，观察七天内的复购变化。
3. 提交后的资料和结果会保存到飞书。接下来读取此前通过真实接口生成的报告，这次录屏没有重新调用 AI。
4. 报告分开列出证据、推断和缺失信息。七天行动包含观察指标与判断条件，模型推断仍需要验证。
5. 填写第一天的虚构指标和结论，点击保存，只更新执行记录，不再调用 AI。刷新后，报告和日志依然保留。
6. 十份虚构资料已经跑通真实接口。失败处理和限制有文档可查。你可以从 GitHub 打开演示，亲自测试。
