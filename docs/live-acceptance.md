## 三个实际错误边界

| 输入/条件 | 返回 | 处理方式 |
| --- | --- | --- |
| 资料中加入明显电话号码 | 422 `invalid_input` | 拒绝并提示修改，不回显敏感内容，不调用 AI |
| 保留 UUID 和私有请求令牌，但修改目标 | 409 `request_content_conflict` | 保留原记录；原资料用于恢复，新资料另建请求 |
| 用正确 UUID 配上伪造访问令牌读取报告 | 403 `record_access_denied` | 在访问飞书前拒绝，不授予其他记录访问权 |

上游超时、AI JSON 不合格、飞书认证/读写失败的恢复路径使用模拟服务测试，不声称本次让供应商在生产环境故障。

## 复现

先配置本地 `.env` 中的 Dify Workflow 和飞书凭证。真实验收会消耗模型额度、写入虚构 DEMO 记录。

```powershell
$env:DEMO_MODE="true"
.\.venv\Scripts\python.exe scripts/prepare_live_table.py --apply
.\.venv\Scripts\python.exe scripts/verify_live_flow.py
```

脚本保留完成证据与本地私有重试状态；再次执行会跳过已经通过的场景。要新建一批验收，请使用不同的 `--output` 和 `--state-file`，不要通过删除飞书记录来重置。
