# 付费试单询盘：可复制的消息草稿

目前尚未确认意向客户。本页是你可以按实际情况修改的草稿，尚未发送，也没有成交或收款记录。

## 第一次联系

> 您好，我用 Codex 辅助搭建了一个个人项目：填写资料后，自动存入飞书、生成固定格式的 AI 分析报告，并回写原记录。可以直接打开演示：[经营验证工作台](https://business-validation-lab.vercel.app/)。如果您有“现有表格需要反复整理成报告”的工作，我想先做一个范围明确的付费试单：接一张表、生成一种报告，用三个样例验收。您是否有适合先验证的小流程？

发送前亲自打开演示完成一次操作，确认能解释输入、报告、存储和恢复。公开演示只填虚构资料。若未亲自操作过，不说“我已经亲自完成验收”；可说项目留有 Codex 辅助执行的验证记录。

## 对方有兴趣时，再确认这五项

> 为了先把范围和验收说清楚，请您提供以下信息。先用虚构样例说明即可：
>
> 1. 现在使用什么表格？哪些列是输入？
> 2. 希望报告包含哪些固定栏目？能否提供一份期望结果？
> 3. 三个验收样例分别是什么？指标的单位、统计时间和达标门槛如何定义？
> 4. 希望何时交付、在哪个环境运行，谁确认验收？
> 5. 可接受的试单预算是多少？模型和部署费用由谁承担？

不索取聊天里的密码或 API key；连接方式确认后，再通过客户控制的私有配置处理。

## 开工前的确认消息

> 本次拟交付：一张飞书数据表、一种固定 JSON 报告、一个 AI 工作流；输入校验、重复请求复用原记录、模型失败后保留输入并恢复，以及配置和交接说明。用双方确认的三个虚构样例验收，包含两次同范围修改。报告中的经营判断需按约定口径核对，不保证经营收益。
>
> 费用：〔双方填写〕；付款节点：〔双方填写〕；模型和部署费用承担方：〔双方填写〕；交付日期及验收日期：〔双方填写〕。
>
> 请核对这份[范围与验收模板](paid-pilot-scope.md)，补齐输入、报告格式、统计口径、运行环境和样例后，我们再确认开工。

占位项必须先协商，不把这段草稿当作已确认报价。七天动作报告不自动包含完整执行日志系统；多表同步、其他报告格式和长期运维需另行确认。

## 收到新需求后怎么判断能否承接

先拿一份虚构输入和期望输出对照现有流程，写清哪些内容可以复用、哪些需要修改。遇到尚未验证的权限、格式或运行条件，先验证再承诺。把客户答复填进范围模板，明确验收人、费用、时间和修改边界；然后才把试单记为“已确认”。

本页可以用于你自行询盘，不会自动给任何人发消息。真实交付完成后，再记录客户能否使用、实际故障和处理结果。
