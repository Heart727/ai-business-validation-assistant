## 二、交付限定为一个表、一种报告

本次只交付一条固定流程：**资料输入 → FastAPI 校验 → 飞书入表 → Dify/DeepSeek 分析 → 校验一种报告 JSON → 回写同一条飞书记录。**

| 包含内容 | 范围上限 |
| --- | --- |
| 资料入口 | 一份字段固定的表单及对应 API；字段与校验要求在开工前确认 |
| 飞书存储 | 一张专用多维表格中的一个数据表；约定字段及资料快照，不扩展到其他表 |
| AI 流程 | 一个 Dify Workflow，使用双方确认的 DeepSeek 模型；生成一种固定结构的报告 |
| 报告与回写 | 一种报告 JSON，校验后更新原记录；不另增 PDF、邮件、幻灯片或其他报告版本 |
| 重复与失败处理 | 同一 UUID、相同资料及凭证重复提交复用原记录；超时或 AI 失败保留输入与已创建的原记录，允许原请求恢复 |
| 验收 | 双方确认的三个样例，以及本模板约定的输入、重复与失败处理检查 |
| 修改 | 两次同范围修改；按第五部分归并反馈 |
| 交接 | 代码、配置说明、字段与 JSON 约定、运行及恢复步骤、实际验收记录 |

不包含第二张表、第二种报告结构、新增模型平台、账号与权限体系、支付功能、跨系统同步、数据迁移、长期运维或经营结果保证。若需要七天执行日志的独立编辑与恢复入口，先另行确认是否纳入范围；报告中包含七天动作，不自动等于附送完整日志系统。

验收环境按第一部分填写。并发防重按双方明确的运行范围核对；单进程验证不自动构成多实例全局唯一性保证。防止重复业务记录也不等于所有重试都只调用一次模型。

## 三、输入和输出先确认，再开始实现

### 输入

资料字段固定为：场景名称、行业、产品或服务、目标客群、经营问题、现有指标、预算范围、目标、时间限制，以及必填 **`success_criteria`（成功判定标准）**。成功标准写明观察指标、统计口径与继续或停止的门槛，不只是重复目标描述。

表单提交须确认资料全部为虚构。三份验收样例默认使用虚构资料；若后续要求处理真实资料，应先另行明确授权、资料范围和存储规则，不直接把公开个人项目接入真实客户表。

请求还包含系统生成的 UUID 和私有请求凭证，用于关联记录与安全恢复；这些不是需要客户公开填写的业务字段。字段长度、必填规则和拒绝条件以双方确认的输入约定为准，服务端也做校验。

### 输出

报告使用一种固定 JSON 结构：

| JSON 字段 | 类型与要求 |
| --- | --- |
| `executive_summary` | 非空文本，说明主要判断与建议验证方向 |
| `observations` | 文本数组，明确区分证据、推断和缺失信息 |
| `risks` | 风险文本数组，数量限制按约定 schema |
| `seven_day_actions` | 七项行动，第 1 至第 7 天各一项 |
| 每项行动的 `day` | 1 至 7 的日期编号，不重复 |
| 每项行动的 `action` | 要做什么 |
| 每项行动的 `metric` | 观察什么指标 |
| 每项行动的 `decision_rule` | 按什么条件继续、停止或补充观察，与输入标准对照 |

资料快照包括原始成功判定标准。报告通过结构校验后，回写该请求已经关联的飞书记录；处理状态、错误码和记录关联信息用于流程管理，不另算一种业务报告。输出校验验证结构与约定内容，不承诺 AI 推断一定正确或保证经营收益。

## 四、三个样例怎么验收

开工前由双方确认三份不同的虚构输入。这里的“三个样例”是计划验收范围，**不是已通过数量**。

| 样例 | 虚构输入 / 版本 | 成功判定标准 | 预期报告与回写要求 | 实际结果 / 证据 |
| --- | --- | --- | --- | --- |
| 样例一 | 待填写 | 待填写 | 完整 JSON、资料快照一致、回写原记录 | 待执行 |
| 样例二 | 待填写 | 待填写 | 完整 JSON、资料快照一致、回写原记录 | 待执行 |
| 样例三 | 待填写 | 待填写 | 完整 JSON、资料快照一致、回写原记录 | 待执行 |

每个样例核对输入到工作流的流转、报告结构及飞书读回；要称为真实集成验收，必须实际使用约定的 Dify/DeepSeek 和飞书，不用 mock 结果替代。记录日期、环境、代码版本、UUID 与原记录关联信息，公开材料不包含密钥或恢复凭证。

另核对以下边界，并在结果里标明测试方式：

- **必填与无效输入**：缺少、留空或只有空格的成功判定标准被拒绝；不把无效请求写成成功记录。
- **重复与内容冲突**：相同 UUID、相同输入和凭证复用原记录；只改成功标准也属于资料变更，不能覆盖旧快照。并发检查按约定运行范围执行。
- **超时与 AI 失败**：通过受控故障注入检查保留输入及已创建的原记录、明确错误提示、原 UUID 恢复及同条回写。注入故障标为模拟，不说供应商实际发生故障。
- **输出不合格**：JSON 不满足 schema 时不标记完成；修正后按原请求恢复。
- **旧版兼容**：如第三部分约定包含旧调用或历史快照兼容，按确认规则检查，不因新增字段破坏已约定的读取或请求路径。

如果飞书创建本身失败，应说明“尚未确认入库”，保留可恢复的输入，不声称已经保留一条不存在的记录。回写结果不确定时，先读回核对，不将错误响应直接当成保存成功。

验收以实际输出与双方确认的范围为准。某项未检查、外部额度不足或环境不可用时，记录为未完成并协商安排，不虚构通过数量，也不把个人项目的旧证据当成本次试单结果。
